# Step 8 — structured independent document review

31 October 2026. Branch: `feature/document-review-checklists-step8`, stacked on Step 7 / PR #21 (`d328b0036a17dfb78a6ee34e9385f115ccaf8b32`). This step does not merge the review stack into main.

## Result

Managers select a current document by another author, open its PDF, confirm a versioned checklist, enter a review note and attest to reviewing the PDF, evidence and limitations. RAMS/CPP have six checks: scope, current sources, proposed content, evidence gaps, risk assessments/controls, and site arrangements. Surveys/specifications have the four document checks. These are application review prompts, not a prescribed safety standard or automated certification.

Acceptance requires every applicable check as an explicit boolean confirmation. The server validates the template version and IDs; missing, false, invented or string-valued confirmations cannot approve a document, including direct API calls. Rejection can record partial checks and reasons. Checklist labels are generated by the server and retained with the decision. New reviews name the preceding decision; a stale reviewer cannot overwrite a newer decision silently.

Each document retains review history with actor, timestamp, decision, note and checklist confirmations. The PDF includes the latest independent review, document fingerprint, recorded checklist version and confirmation results. Its current status is recalculated against live source/document revisions. Source changes and new document revisions still reopen review; previous evidence and decisions remain stored.

Review forms appear only for managers, and self-authored, superseded or stale documents are excluded from selection. Existing server role, project access, independent-author, source and attestation checks remain in force. Completion clears the form's confirmations; selecting another document starts a new checklist.

## Upgrade behaviour

Older review records remain historical evidence. An accepted review without the complete current checklist displays **Historical review — structured checklist required**, rather than being silently treated as checklist-complete. An independent manager can record a fresh decision against the current document; the old record remains in history. The record schema is additive and needs no database migration.

The existing bundled DejaVu fonts are now embedded in document PDFs, fixing the poor spacing/font substitution seen during visual inspection. The coloured risk matrix remains a browser authoring aid, as in Step 6; PDF risk ratings remain textual. Checklist confirmations are recorded human assertions, not digital signatures, proof of professional competence or authority to commence work. AI generation remains disabled.
